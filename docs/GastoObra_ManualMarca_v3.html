01

Identidad de Marca

Gasto Obra es una herramienta de control de gastos para obras y refacciones. La marca debe transmitir confianza, solidez y profesionalismo — como un capataz que lleva las cuentas con precisión.

Esencia

La identidad visual de Gasto Obra se construye sobre dos pilares: el ámbar cálido del casco de obra y el oliva terroso de la tierra que se pisa en una construcción. Estos dos colores anclan toda la paleta y definen el tono visual: cálido, terrenal, confiable.

Personalidad

  • Confiable — La gente confía dinero real a esta app. Cada decisión visual refuerza seriedad.
  • Terrenal — Colores de obra, no de startup. Ámbar, oliva, tierra, acero.
  • Claro — Los datos financieros necesitan claridad absoluta. Jerarquía nítida, sin ruido.
  • Profesional — Premium sin ser lujoso. Funcional sin ser frío.

Colores Semilla

Extraídos directamente del logo, estos dos colores son el ADN de toda la paleta.

Sistema de Logo

El logo combina un ícono de casco de obra ilustrado con la wordmark "gasto obra" en la tipografía Space Grotesk. Se presenta en cuatro variantes.

Variantes del Logo

Horizontal / Fondo oscuro
Horizontal / Fondo claro
Vertical / Fondo oscuro
Ícono solo / Favicon

Descripción del Logo

  • El casco de obra ilustrado es inmediatamente reconocible y comunica "construcción" sin ambigüedad
  • El estilo ilustrativo con trazos gruesos le da personalidad — no es un ícono genérico de Material Design
  • El detalle del protector de nuca (neck flap) lo diferencia de un casco genérico y le agrega autenticidad
  • La silueta es fuerte y se mantiene legible a diferentes tamaños
  • La wordmark "gasto obra" en minúsculas con la tipografía Space Grotesk es amigable, moderna y directa
  • La combinación de ícono + wordmark funciona en horizontal (navbar, header) y vertical (landing, splash)

Tipografía

Dos familias con roles claros: Space Grotesk para la marca y display, Red Hat Display para toda la interfaz.

Space Grotesk — Tipografía de Marca & Display

Se usa exclusivamente en el logo wordmark ("gasto obra"). No se usa en la UI del dashboard. Es una fuente display geométrica con personalidad fuerte.

Wordmark

gasto obra

Space Grotesk Bold · Logo y display · Google Fonts

Space Grotesk: Se usa en la wordmark del logo y como fuente display en el dashboard (títulos, precios, encabezados). Se carga desde Google Fonts.

Red Hat Display — Tipografía de UI

Toda la interfaz usa Red Hat Display. Es una sans-serif geométrica con toque humanista, diseñada por Red Hat para pantalla. Excelente legibilidad en tamaños pequeños, personalidad en tamaños grandes.

05

Design Tokens

Tokens CSS y su mapeo a Tailwind. Prefijo: go-. Todas las propiedades CSS usan el formato --go-*.

CSS Custom Properties

Copiar este bloque completo en assets/css/main.css:

/* ── Gasto Obra Design Tokens ── */ :root { /* Surfaces */ --go-bg: #171A14; --go-bg-elevated: #2C261E; --go-surface: #24271F; --go-surface-hover: #2E312A; --go-surface-alt: #353830; --go-border: #3D4036; --go-border-subtle: #2E312A; /* Primary */ --go-primary: #FFAB40; --go-primary-hover: #FFBC62; --go-primary-active: #E99A35; --go-primary-muted: rgba(255, 171, 64, 0.12); --go-primary-on: #1A1200; /* Secondary */ --go-secondary: #6B8F71; --go-secondary-hover: #7DA383; --go-secondary-muted: rgba(107, 143, 113, 0.12); /* Semantic */ --go-success: #5CB870; --go-success-muted: rgba(92, 184, 112, 0.12); --go-danger: #D4544A; --go-danger-muted: rgba(212, 84, 74, 0.12); --go-warning: #E8B83A; --go-warning-muted: rgba(232, 184, 58, 0.12); --go-info: #5A9BBF; --go-info-muted: rgba(90, 155, 191, 0.12); /* Text */ --go-text: #F0EBE1; --go-text-secondary: #B5B0A4; --go-text-tertiary: #8A8579; --go-text-muted: #5E594F; --go-text-inverse: #171A14; /* Categories */ --go-cat-materiales: #5A8FB8; --go-cat-herramientas: #D4793D; --go-cat-transporte: #BFA63D; --go-cat-mano-de-obra: #A86B5E; --go-cat-comida: #6B9B6B; --go-cat-otros: #8B847A; /* Payment Methods */ --go-pay-transferencia: #5A8FB8; --go-pay-efectivo: #6B9B6B; --go-pay-tarjeta: #8B6BA3; --go-pay-mercadopago: #00B1EA; /* Typography */ --go-font-ui: 'Red Hat Display', system-ui, sans-serif; /* Radius */ --go-radius-sm: 6px; --go-radius-md: 10px; --go-radius-lg: 14px; --go-radius-xl: 18px; --go-radius-full: 9999px; }

Tailwind Config Mapping

Actualizar tailwind.config.js para consumir los tokens CSS:

/** @type {import('tailwindcss').Config} */ export default { content: ["./components/**/*.{js,vue,ts}", "./layouts/**/*.vue", "./pages/**/*.vue", "./plugins/**/*.{js,ts}", "./utils/**/*.{js,ts}", "./app.vue", "./error.vue"], theme: { extend: { fontFamily: { ui: ['Red Hat Display', 'system-ui', 'sans-serif'], }, colors: { go: { bg: 'var(--go-bg)', 'bg-elevated': 'var(--go-bg-elevated)', surface: 'var(--go-surface)', 'surface-hover':'var(--go-surface-hover)', 'surface-alt': 'var(--go-surface-alt)', border: 'var(--go-border)', 'border-subtle':'var(--go-border-subtle)', primary: 'var(--go-primary)', 'primary-hover':'var(--go-primary-hover)', 'primary-active':'var(--go-primary-active)', 'primary-muted':'var(--go-primary-muted)', 'primary-on': 'var(--go-primary-on)', secondary: 'var(--go-secondary)', success: 'var(--go-success)', 'success-muted':'var(--go-success-muted)', danger: 'var(--go-danger)', 'danger-muted': 'var(--go-danger-muted)', warning: 'var(--go-warning)', 'warning-muted':'var(--go-warning-muted)', info: 'var(--go-info)', 'info-muted': 'var(--go-info-muted)', text: 'var(--go-text)', 'text-secondary':'var(--go-text-secondary)', 'text-tertiary':'var(--go-text-tertiary)', 'text-muted': 'var(--go-text-muted)', }, }, borderRadius: { 'go-sm': 'var(--go-radius-sm)', 'go-md': 'var(--go-radius-md)', 'go-lg': 'var(--go-radius-lg)', 'go-xl': 'var(--go-radius-xl)', }, }, }, plugins: [], }
Uso en templates: Con esta configuración, se usa bg-go-surface, text-go-primary, border-go-border, etc. Todos los colores se resuelven a CSS variables, lo que hace trivial agregar light mode en el futuro cambiando solo los valores de las custom properties.

Implementación en utils/index.ts

Reemplazar los hex hardcodeados con referencias a las CSS variables. Para JavaScript donde se necesiten valores directos (ej: charts), definir un objeto que refleje los tokens:

// utils/index.ts — Category colors (replaces hardcoded hex) export const CATEGORY_COLORS: Record<string, string> = { materiales: '#5A8FB8', herramientas: '#D4793D', transporte: '#BFA63D', 'mano de obra': '#A86B5E', comida: '#6B9B6B', otros: '#8B847A', } export const PAYMENT_METHOD_COLORS: Record<string, string> = { transferencia: '#5A8FB8', efectivo: '#6B9B6B', tarjeta: '#8B6BA3', mercadopago: '#00B1EA', } // For category badges in templates, prefer CSS: // :style="{ background: CATEGORY_COLORS[cat] + '1F', color: CATEGORY_COLORS[cat] }" // (0x1F = ~12% opacity in hex alpha)

08

Implementación

Guía paso a paso para aplicar este sistema de marca al codebase existente durante Phase 3.

Orden de Aplicación

  • Paso 1 — Tokens CSS: Agregar el bloque de custom properties en main.css. No rompe nada existente.
  • Paso 2 — Tailwind config: Reemplazar el tailwind.config.js con la nueva configuración que consume los tokens.
  • Paso 3 — Fuente: Agregar el link de Google Fonts en nuxt.config.ts y setear font-family en el body.
  • Paso 4 — main.css: Reescribir las clases utilitarias (btn-primary, modal-*, etc.) usando los nuevos tokens.
  • Paso 5 — Layouts: Migrar default.vue y landing.vue a los nuevos colores y fuente.
  • Paso 6 — Componentes: Migrar cada componente, reemplazando clases de Tailwind genéricas (bg-gray-800, text-gray-300) con las semánticas (bg-go-surface, text-go-text-secondary).
  • Paso 7 — JS colors: Actualizar utils/index.ts con los nuevos colores de categoría y pago.
  • Paso 8 — Logo: Reemplazar el texto "Gasto Obra" en AppHeader con el SVG del logo horizontal.

Light Mode (futuro)

El sistema de tokens está diseñado para soportar light mode. Cuando se implemente, solo hay que agregar un bloque que sobreescriba las variables:

/* Light mode override (futuro) */ [data-theme="light"] { --go-bg: #F5F0E5; --go-bg-elevated: #FDFBF6; --go-surface: #FFFFFF; --go-surface-hover: #F0EBE1; --go-border: #D9D3C7; --go-text: #2A2520; --go-text-secondary: #5E594F; --go-text-tertiary: #8A8579; --go-text-muted: #B5B0A4; --go-primary: #E99A35; /* slightly darker for light bg contrast */ /* ... etc */ }
Clave: Porque TODO el sistema visual pasa por las custom properties --go-*, cambiar de dark a light es solo cambiar valores — cero cambios en componentes, cero cambios en Tailwind classes.
