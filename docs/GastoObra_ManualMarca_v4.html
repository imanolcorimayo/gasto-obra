Primario en modo claro

El ámbar se oscurece levemente para mantener contraste WCAG AA sobre fondos claros.

#FFAB40 → #E99A35
Dark primary → Light primary
#5CB870 → #3E9954
Success dark → light
#D4544A → #C74840

¿Por qué warm off-white y no blanco puro? El blanco puro (#FFFFFF) se usa solo para las cards (surfaces). La página en sí (#F5F0E8) tiene un tinte cálido que evoca papel de obra, planos, documentos de campo. Evita la sensación de "app de hospital" y mantiene coherencia con la identidad terrenal de la marca.

Tailwind Config — darkMode class

Cambio mínimo al config existente: agregar darkMode: 'class' y consumir los tokens via CSS variables.

/** @type {import('tailwindcss').Config} */ export default { content: ["./components/**/*.{js,vue,ts}", "./layouts/**/*.vue", "./pages/**/*.vue", "./app.vue", "./utils/**/*.{js,ts}"], // ← La clave: dark mode por clase en <html> darkMode: 'class', theme: { extend: { fontFamily: { ui: ['Red Hat Display', 'system-ui', 'sans-serif'], }, colors: { go: { // Todos resuelven a CSS variables → tema automático bg: 'var(--go-bg)', 'bg-elevated': 'var(--go-bg-elevated)', surface: 'var(--go-surface)', 'surface-hover':'var(--go-surface-hover)', 'surface-alt': 'var(--go-surface-alt)', border: 'var(--go-border)', 'border-subtle':'var(--go-border-subtle)', primary: 'var(--go-primary)', 'primary-hover':'var(--go-primary-hover)', 'primary-muted':'var(--go-primary-muted)', 'primary-on': 'var(--go-primary-on)', secondary: 'var(--go-secondary)', success: 'var(--go-success)', 'success-muted':'var(--go-success-muted)', danger: 'var(--go-danger)', 'danger-muted': 'var(--go-danger-muted)', warning: 'var(--go-warning)', 'warning-muted':'var(--go-warning-muted)', info: 'var(--go-info)', 'info-muted': 'var(--go-info-muted)', text: 'var(--go-text)', 'text-secondary':'var(--go-text-secondary)', 'text-tertiary':'var(--go-text-tertiary)', 'text-muted': 'var(--go-text-muted)', }, }, borderRadius: { 'go-sm': 'var(--go-radius-sm)', 'go-md': 'var(--go-radius-md)', 'go-lg': 'var(--go-radius-lg)', 'go-xl': 'var(--go-radius-xl)', }, }, }, plugins: [], }
Por qué CSS variables + Tailwind (no Tailwind dark: puro): Con este enfoque, todos los componentes solo necesitan bg-go-surface — sin dark:bg-go-surface-dark. Cambiar de tema es cambiar variables, no clases. Los componentes no saben qué tema están mostrando. Agregar light mode en el futuro requiere cero toques a los templates.

05

useTheme — Composable

Un composable Nuxt 3 para manejar el toggle y persistir la preferencia en localStorage. Se agrega en composables/useTheme.ts.

// composables/useTheme.ts import { ref, computed, onMounted } from 'vue' type Theme = 'dark' | 'light' const STORAGE_KEY = 'go-theme' const DEFAULT_THEME: Theme = 'light' // ← light como default // Estado compartido entre todos los componentes const currentTheme = ref<Theme>(DEFAULT_THEME) export function useTheme() { const isDark = computed(() => currentTheme.value === 'dark') const isLight = computed(() => currentTheme.value === 'light') function applyTheme(theme: Theme) { currentTheme.value = theme if (process.client) { document.documentElement.classList.toggle('light', theme === 'light') localStorage.setItem(STORAGE_KEY, theme) } } function toggle() { applyTheme(currentTheme.value === 'dark' ? 'light' : 'dark') } // Leer preferencia guardada al montar onMounted(() => { const saved = localStorage.getItem(STORAGE_KEY) as Theme | null const systemPrefers = window.matchMedia('(prefers-color-scheme: dark)').matches const resolved: Theme = saved ?? (systemPrefers ? 'dark' : 'light') applyTheme(resolved) }) return { currentTheme, isDark, isLight, toggle, applyTheme } }
Lógica de resolución: Si el usuario ya eligió un tema → se usa. Si no → se detecta la preferencia del sistema (prefers-color-scheme). Esto respeta tanto la elección explícita como las preferencias del OS.

Toggle en AppHeader.vue

<!-- Agregar en AppHeader.vue, junto al botón "Salir" --> <script setup lang="ts"> const { isDark, toggle } = useTheme() </script> <template> <!-- ... logo, user ... --> <button @click="toggle" class="p-2 rounded-go-md text-go-text-tertiary hover:text-go-text hover:bg-go-surface-hover transition-colors" :aria-label="isDark ? 'Cambiar a modo claro' : 'Cambiar a modo oscuro'" > <<!-- Sol (modo claro activo) --> <svg v-if="isDark" width="18" height="18" ...> <!-- sol icon --> </svg> <<!-- Luna (modo oscuro activo) --> <svg v-else width="18" height="18" ...> <!-- luna icon --> </svg> </button> </template>

06

Guía de Migración

Pasos ordenados para migrar el dashboard al sistema dual-tema. Cada paso es atómico y testeable.

1
CSS Variables en main.css
Reemplazar el bloque :root actual con el nuevo bloque que incluye ambos temas (Sección 03 de este manual). No toca ningún componente.
2
Tailwind config — darkMode: 'class'
Reemplazar tailwind.config.js con la nueva versión (Sección 04). Renombrar tokens: bg-base → bg-go-bg, bg-surface → bg-go-surface, etc.
3
useTheme composable
Crear composables/useTheme.ts (Sección 05). Agregar el toggle al AppHeader.vue. Verificar que el toggle cambia la clase en <html>.
4
Fuente + body en app.vue
Agregar Google Fonts link en nuxt.config.ts. Setear font-family: var(--go-font-ui) en body dentro de main.css. Y background: var(--go-bg); color: var(--go-text).
5
Migrar main.css utility classes
Actualizar btn-primary, modal-*, btn-secondary para usar var(--go-*) tokens en vez de valores hardcodeados. Como son CSS classes reales (no Tailwind), responden automáticamente al cambio de variables.
6
Migrar layouts y componentes
En todos los componentes: reemplazar bg-gray-800 → bg-go-surface, text-gray-100 → text-go-text, border-gray-700 → border-go-border, bg-base → bg-go-bg. Ver tabla completa en v3 Sección 05.
7
Logo SVG en AppHeader
Reemplazar el texto "Gasto Obra" en AppHeader.vue con el SVG del logo horizontal. El ícono del logo usa currentColor para el wordmark, adaptándose a ambos temas.
8
Actualizar utils/index.ts
Actualizar los colores hardcodeados de categorías y métodos de pago con los nuevos valores (los colores de categoría son los mismos en ambos temas).
